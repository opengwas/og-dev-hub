Epic #307: OGS-00009 after measurement (#322)

The release was built once, on 13 November 2026 at 8acd22b: 2,514 Analyses, GWAS-VCF sources, 9,846,427 observed variants and 11,133,427 variants after Reference Completion. The measured reader path is still per-row GWAS-VCF: #316’s integer join applies, but #318/#319’s FinnGen/GWAS-SSF batches do not.

The after-artifact derives each phase, its October baseline and every epic projection from records. The baseline includes backup contention; these are not matched-load before/after trials. Backups were reported to have stopped covering this filesystem on 2 November; the recorded 13 November run showed no corresponding I/O slowdown. Its duration would not fit between the old 15-hour backup windows, even had those still applied.

The evening criterion is missed

The successful run spans 02:01:00.470425–12:13:58.044016 UTC: 36,777.574 s (10h12m57.574s), 4,377.574 s (1h12m57.574s) above nine hours. The earlier failed argument-check launch is excluded. No publication or registration was performed.

Completion’s timer summary attributes 16,443.2 s to LD-block fits, 4,060.9 s to the Top-Hit Index, 1,149.1 s to band writing, 675.5 s to checkpoint merge and 215.6 s to axis construction. These summaries have finer resolution than the integer-second log spans in the after-artifact. The unchanged LD-block phase is 44.7% of the release and the principal milestone miss. Cheaper fits remain #423’s Reference Completion Method question. At that revision completion did not forward its worker count to the Top-Hit Index scan: that phase was single-process despite complete-dense --n-workers 32. Issue #435 now forwards it; the separate completed-Store measurement below does not replace this historical whole-release result.

Every phase projection is met at the harness’s stated 5%/one-second tolerance except Pass 2: 34m55s against approximately 30 minutes, still using per-row GWAS-VCF. The epic’s narrower six-step sum is 9h49m16s, meeting its 19.4, 18.2 and 16.3-hour scenarios. That sum omits steps and is not milestone #388’s end-to-end result. The corresponding October six-step sum is 44h02m15s, not the epic’s partly extrapolated approximately 27 hours.

Correctness and the full-size #312 proof

Both 32-worker validation records report ok: true, no errors, findings or warnings. The completed Store’s Observed-View Check reports passed: true. No single-worker re-validation was run.

The separately authorised 15 November standalone Top-Hit Index rebuild took 158.053 s at 32 workers. Its comparison finds all 24 arrays exactly equal, including every group/tier attribute. All tiers span three 1,024-Analysis column bands:

Tier Hits Hits in the three bands
5e-4 41,910,434 17,140,593 / 16,979,702 / 7,790,139
5e-6 11,020,928 4,715,139 / 4,185,164 / 2,120,625
5e-8 5,491,751 2,424,406 / 2,030,242 / 1,037,103

The read-only harness is now committed as benchmarks/compare_top_hits.py, recovered from scratch/322/run/compare_top_hits.py. Its provenance note pins the original result and both harness sources by SHA-256 and records the exact reproduction invocation. The original full-size JSON and its numbers were not rewritten or remeasured for this review. From this worktree, using only the two already-built Stores:

pixi run -e dev python benchmarks/compare_top_hits.py \
  /data/opengwasdb/work/orchestrate/opengwasdb-307/scratch/322/OGS-00009/store.opengwasdb \
  /data/opengwasdb/work/orchestrate/opengwasdb-307/scratch/322/offclock/tophits/store.opengwasdb \
  --output /data/opengwasdb/work/orchestrate/opengwasdb-307/scratch/322/fix1/top-hits-reproduced.json

This command is documented, not executed again in the review round. It compares the decoded index arrays and group/tier attributes and returns the three-band counts above; it cannot write its report inside either input Store.

This proof is outside the timed release; it is not a second Store build. Its scratch copy occupied 64 GiB, more than the authorisation’s estimated 47 GiB. The off-clock guard sampled available memory and free disk throughout copying and both comparisons, with 200 GiB / 1 TiB stop thresholds. The standalone step’s sampled private-memory peak was 12.0 GiB, minimum available 916 GiB.

The published comparison completed once, read-only, in 412.60 s. The attribution reads its outputs, Admission Record and eight variant metadata rows, not the statistic planes. It accounts for the differences as follows:

  • #376: 1,271 published-only rows, all off-primary contig lifts. No rebuilt-only rows; all 9,846,427 remaining rows match by ALID in the same order.
  • Engine #357’s conflicting-duplicate rule (ADR 0072): 15,226 published-only associations across eight variants. The Admission Record logs exactly 30,452 rejected source rows, two per affected Analysis/variant, matching every absence count. These include the three collisions described by #325, but this measurement does not declare that still-open issue resolved.
  • Z: zero differing values where both releases retain an association.
  • #355 and the residual refit: 14,079,650,231 SE values differ: 5,002,503 are direct float16 roundings; 13,788,253,543 are within the two codecs’ bound; 286,394,185 exceed that codec-only bound. The old Dense build narrowed every SE before fitting, not just exceptions. Adding its historical float16 log half-step gives 0.004425169954, above the observed maximum absolute log ratio 0.004152023438 (codec-only bound 0.003937007874). These counts are retained unchanged, not relabelled or hidden by loosening the comparator. The envelope accounts for the historical representation; it is not an exact source-fidelity comparison.
  • EAF: 1,544 differing retained values, exclusively at four of the conflicting variants. Removing the conflicting observations changes all four EAF Baselines and hence residual quantisation; no other variant has an EAF value difference.
  • #381: format 0.2.2 is used, but this pair needs zero respelled ALIDs. A format move does not imply this particular source changes allele order.

The aligned comparator now refuses different Reference Assemblies and permits opposite-order historical indel pairing only across pre-0.2.2 sorted versus 0.2.2+ reference-first semantics. Opposite-order indels in two reference-first Stores remain distinct insertion/deletion identities. This pair declares GRCh38 on both sides and has zero respelled rows, so the original evidence and strict SE counts remain unchanged; the full-size comparison was not repeated.

No additional difference class remains unexplained. The full source-by-source fidelity of every retained cell was not remeasured; clean validation and the bounded release comparison should not be mistaken for that stronger proof.

Completion scan worker forwarding (#435)

On 16 November 2026, at committed 8954c7fa, the existing production build-dense-top-hits command rebuilt the completed OGS-00009 index on a private reflink, never on #322’s authoritative completed Store. Dense completion and Hybrid’s initial and post-crossover scans now pass their existing worker request to this same implementation. The public default remains one; Ragged harvesting and #423’s fit method are unchanged.

The measurement record preserves argv, commit, UTC timestamps, start/end uptime, memory planning and artifact hashes. The run held $RD/timing.lock, 08:06:37.434361–08:10:13.705053 UTC. The production log reports 32 requested and 32 effective workers, not an uncapped promise that every host gets 32. The unchanged cap allowed a 236,522 MiB budget, a quarter of available memory at pool creation. The grid was 11,133,427 × 2,514, scanned in 2,784 bands of 4,000 rows, under the unchanged 1 GiB decoded-band budget.

Phase Seconds
Scan 191.1
Tier write 22.3
Production CLI wall time (time -v) 216.23

The phases are rounded to tenths by the production logger. The time -v record includes a maximum RSS of 7,048,836 KiB; that is not aggregate pool memory. Before starting, the conservative estimate was 102,579,642,368 bytes, including worker units, held results and a 16 GiB parent/writer allowance, below the quarter-available 248,305,688,576 bytes. Ten-second free -g samples never fell below 910 GiB available; a 200 GiB guard remained armed.

The committed comparator’s result finds all 27 arrays exactly equal, with all group/tier attributes equal. This completed index has the observed index’s 24 arrays plus three imputed arrays, one per tier. Hit counts are 47,805,439 / 12,750,070 / 6,405,322 at 5e-4 / 5e-6 / 5e-8, each spanning three Analysis column bands. analyses.tsv is byte-identical, including every n_hits_* value (SHA-256 66dfa6cc67dfde289198061417bf3b5dde0fd33a43bf79be15bd963270200138). The source’s 564-file manifest/Analytical Metadata/index hash inventory is unchanged before and after; the inventories and guard driver remain under $RD/scratch/435/.

This is one standalone rebuild, not a second whole Store build or Reference Completion. The earlier 4,060.9-second completion phase was measured on another date, not a matched-load serial control. No new end-to-end time is claimed, and the unwaived nine-hour decision remains separate. Reproduce the read-only comparison, not the rebuild, from this worktree with:

Profiles and language decision

The profile artifact summarises all recorded whole-tree snapshots and three native worker recordings, with input hashes. Native 790 pooled active samples put 53.9% in OpenBLAS/numpy C/scikit-learn Cython, 28.6% in Python frames and 17.5% in other native code. The draft’s 70% was the first recording alone and is superseded by this pooled result. Non-native frames around numpy operations are not evidence of interpreter time. The eight reader frames named by ADR 0081 account for 90,160 of 114,751 Pass 2 worker samples across two snapshots: 78.57% pooled, approximately 79%, correcting the draft’s 87% for that same frame set.

ADR 0081 records the owner’s acceptance on 16 November 2026: no compiled extension after #307; retain Python/Numba. Reconsider only if profiling after the columnar GWAS-VCF reader and column-major band-write work identifies a dominant interpreted per-row kernel that cannot be vectorised. The follow-ups are to vectorise the remaining GWAS-VCF reader, benchmark column-major Dense bands, and budget the SE rewrite pool; #435’s completion index worker forwarding is measured above. The SE rewrite’s sampled 323.5 GiB private peak exceeded the initial approximately 233 GiB plan; available memory never fell below 625 GiB. No new solver or numerical method was introduced here.
